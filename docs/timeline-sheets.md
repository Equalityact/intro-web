# 구글 스프레드시트로 타임라인 관리하기

한 번 연결한 뒤에는 스프레드시트의 행을 추가·수정하면 사이트에 반영됩니다. 매번 코드를 수정하거나 다시 배포할 필요가 없습니다. 처음 연결할 때만 Vercel 환경 변수 설정과 배포가 필요합니다.

## 1. 현재 타임라인 가져오기

1. [가져오기용 CSV](../content/timeline-sheet.csv)를 내려받습니다. 기존 사건 11개와 링크 37개가 들어 있습니다.
2. 구글 스프레드시트를 만들고 **파일 → 가져오기 → 업로드**에서 CSV를 불러옵니다. 구분자는 쉼표입니다.
3. 가져오기 옵션에 ‘텍스트를 숫자, 날짜, 수식으로 변환’이 있으면 해제합니다. 본문과 링크는 텍스트 그대로 유지합니다.

| 열 | 작성 방법 |
| --- | --- |
| 시기 | `22대 국회`처럼 묶음 이름을 각 행에 적습니다. 같은 이름의 사건들은 함께 표시됩니다. |
| 제목 | 사건 제목을 적습니다. 필수입니다. |
| 본문 | 설명을 적습니다. 빈 줄로 문단을 나눌 수 있으며, 제목만 표시하려면 비워도 됩니다. |
| 공개 | `예` 또는 `TRUE`는 표시, `아니오` 또는 `FALSE`는 사이트에서 숨깁니다. 빈칸은 표시입니다. |

행 하나가 사건 하나입니다. 시기는 처음 등장하는 행의 순서대로, 같은 시기의 사건들은 시트의 행 순서대로 표시합니다. 새로운 시기 이름을 입력하면 해당 구역과 상단 앵커 메뉴도 자동 생성됩니다.

본문 링크는 `[표시할 문구](https://주소)`로 입력합니다. 일반 텍스트와 링크만 지원하며 HTML은 실행하지 않습니다. 기존 원고처럼 괄호와 법안 제목에 서로 다른 링크가 붙어 있으면 각각 따로 유지합니다. 셀에 설정한 별도의 하이퍼링크 서식은 CSV에 포함되지 않으므로 본문에 이 표기법으로 적어야 합니다.

## 2. 타임라인 탭을 CSV로 게시하기

1. **파일 → 공유 → 웹에 게시**를 선택합니다.
2. 문서 전체 대신 타임라인 탭을 선택하고, 형식을 **쉼표로 구분된 값(.csv)**로 바꿉니다.
3. 게시 후 만들어진 주소를 복사합니다. 주소 끝에 `output=csv`가 있어야 합니다.
4. 게시 설정의 **변경사항이 있으면 자동으로 다시 게시**가 켜져 있는지 확인합니다.

웹에 게시한 탭의 원본 데이터는 공개됩니다. `공개=아니오`는 사이트 표시만 숨기므로, 공개할 자료만 넣은 타임라인 전용 탭을 사용합니다.

## 3. Vercel에 한 번 연결하기

`Equalityact/intro-web` 저장소와 연결된 Vercel 프로젝트의 **Settings → Environment Variables**에서 다음 값을 추가합니다.

```text
이름: TIMELINE_SHEET_CSV_URL
값: 앞 단계에서 복사한 게시 CSV 주소
```

먼저 **Preview** 환경에 설정하고 검토용 브랜치를 다시 배포해 확인합니다. 운영 반영이 승인되면 같은 값을 **Production** 환경에도 설정하고 운영 배포합니다. 환경 변수 변경은 이미 완료된 배포에 소급 적용되지 않습니다.

게시 CSV 주소는 브라우저에서 직접 가져오지 않고 `/api/timeline` 서버 경로에서 읽습니다. 별도의 구글 API 키나 서비스 계정은 필요하지 않습니다.

## 4. 갱신 확인하기

- `/timeline`을 열면 최신 시트를 읽고, 열린 페이지는 1분마다 다시 확인합니다. 다른 탭을 보다가 돌아와도 확인합니다.
- 서버 캐시는 1분이며 구글 게시 내용의 갱신에도 시간이 걸릴 수 있어, 수정 내용은 보통 몇 분 안에 보입니다. 즉시 반영을 보장하는 실시간 편집 방식은 아닙니다.
- `/api/timeline`에 `version: 1`과 사건 목록이 나오면 연결된 것입니다.
- 시트 주소가 없거나 접근이 막히면 원래의 정적 타임라인을 유지합니다. 읽는 도중 갱신에 실패하면 이미 불러온 내용을 유지합니다.
- 필수 열 누락, 비정상 링크, 잘못된 행은 일부만 게시하지 않고 해당 갱신 전체를 적용하지 않습니다. 최소 한 사건은 공개되어 있어야 합니다.
- 기존 시기 이름을 유지하면 `#p17`, `#p22` 같은 기존 앵커 주소도 유지됩니다.

## 로컬 확인

`.env.example`을 `.env`로 복사하고 게시 CSV 주소를 넣은 뒤 `npm run dev`를 실행합니다. 서버가 실행 중이었다면 다시 시작합니다. `.env`는 Git에 저장하지 않습니다.

```sh
npm run export:timeline
npm run check
```

`export:timeline`은 저장소의 원고로 가져오기 파일을 다시 만듭니다. 이미 연결한 구글 시트를 덮어쓰거나 수정하지 않습니다. `check`는 기존 원고·링크 검사와 CSV 변환·API 동작 검사를 실행합니다. 실제 구글 시트에 연결되었는지는 별도로 게시 주소와 `/api/timeline` 응답을 확인합니다.
