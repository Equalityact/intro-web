# 구글 스프레드시트로 타임라인 관리하기

현재 전달받은 스프레드시트를 기본 데이터 원본으로 설정했습니다. 이 설정이 포함된 버전을 한 번 배포한 뒤에는 시트의 행을 추가·수정하기만 하면 됩니다. 별도 Apps Script, 구글 API 키, 서비스 계정이나 필수 Vercel 환경 변수는 필요하지 않습니다.

연결된 문서: https://docs.google.com/spreadsheets/d/1tk_3uh5HVxkfsERAzj7nusZsGR4gCRj4UlZ1R49REhY/edit

연결 탭은 `gid=0`이며, 주소는 `content/timeline-source.json`에 저장되어 있습니다. 현재 공유 상태에서 로그인 없이 CSV를 읽을 수 있음을 확인했습니다. 보기 권한을 유지하면 별도로 ‘웹에 게시’를 할 필요도 없습니다.

## 1. 현재 타임라인 가져오기

1. [가져오기용 CSV](../content/timeline-sheet.csv)를 내려받습니다. 기존 사건 11개와 링크 37개가 들어 있습니다.
2. 구글 스프레드시트를 만들고 **파일 → 가져오기 → 업로드**에서 CSV를 불러옵니다. 구분자는 쉼표입니다.
3. 가져오기 옵션에 ‘텍스트를 숫자, 날짜, 수식으로 변환’이 있으면 해제합니다. 본문과 링크는 텍스트 그대로 유지합니다.

| 열 | 작성 방법 |
| --- | --- |
| 시기 | `22대 국회`처럼 묶음 이름을 각 행에 적습니다. 같은 이름의 사건들은 함께 표시됩니다. |
| 분류 | `정부`, `권고`, `입법`, `시민행동`을 입력하면 카드의 작은 구분 표시에 반영됩니다. 빈칸으로 두면 표시하지 않습니다. |
| 제목 | 사건 제목을 적습니다. 필수입니다. |
| 본문 | 설명을 적습니다. 빈 줄로 문단을 나눌 수 있으며, 제목만 표시하려면 비워도 됩니다. |
| 공개 | `예` 또는 `TRUE`는 표시, `아니오` 또는 `FALSE`는 사이트에서 숨깁니다. 빈칸은 표시입니다. |

행 하나가 사건 하나입니다. 시기는 처음 등장하는 행의 순서대로, 같은 시기의 사건들은 시트의 행 순서대로 표시합니다. 새로운 시기 이름을 입력하면 해당 구역과 상단 앵커 메뉴도 자동 생성됩니다.

현재 가져오기 파일은 `시기·분류·제목·본문·공개` 5열입니다. 이전 4열 시트도 계속 지원하며 기존 사건은 저장된 표시 정보를 사용합니다. `기간`, `연도`, `주체` 열을 선택적으로 추가하면 기간 배지와 카드 상단의 연도·주체도 직접 관리할 수 있습니다. 기간은 같은 시기 안에서 동일하게 적습니다. 새 사건은 기존 분류를 임의로 추정하지 않으며 입력한 분류만 표시합니다. 제목이 `기관명(연도) - 사건 제목` 형식이면 연도와 주체를 나누어 보여줍니다.

새 국회로 넘어갈 때는 기존 5열 뒤에 F열 `기간`을 추가하고, 해당 시기의 첫 사건 행에 `2028~2032`처럼 적습니다. 나머지 같은 시기 행은 기간을 비워도 됩니다. 기존 시기의 기간을 비워두면 저장된 표시를 유지하고, 새 시기의 기간을 비워두면 배지를 생략합니다. 시기와 순번은 시트 행에 따라 자동 생성하며 국회 기간을 임의로 추정하지 않습니다.

본문 링크는 `[표시할 문구](https://주소)`로 입력합니다. 일반 텍스트와 링크만 지원하며 HTML은 실행하지 않습니다. 기존 원고처럼 괄호와 법안 제목에 서로 다른 링크가 붙어 있으면 각각 따로 유지합니다. 셀에 설정한 별도의 하이퍼링크 서식은 CSV에 포함되지 않으므로 본문에 이 표기법으로 적어야 합니다.

## 2. 다른 시트로 바꿀 때

현재 시트에는 이 단계가 필요하지 않습니다. 다른 문서로 교체할 때는 익명으로 읽을 수 있는 공유 CSV 주소를 사용하거나 아래 방법으로 CSV를 게시합니다.

1. **파일 → 공유 → 웹에 게시**를 선택합니다.
2. 문서 전체 대신 타임라인 탭을 선택하고, 형식을 **쉼표로 구분된 값(.csv)**로 바꿉니다.
3. 게시 후 만들어진 주소를 복사합니다. 주소 끝에 `output=csv`가 있어야 합니다.
4. 게시 설정의 **변경사항이 있으면 자동으로 다시 게시**가 켜져 있는지 확인합니다.

웹에 게시한 탭의 원본 데이터는 공개됩니다. `공개=아니오`는 사이트 표시만 숨기므로, 공개할 자료만 넣은 타임라인 전용 탭을 사용합니다.

## 3. 배포와 선택적 환경 변수

현재 시트 주소는 기본 설정에 포함되어 있으므로 Vercel 환경 변수 추가는 필수가 아닙니다. 이번 변경이 포함된 검토용 배포에서 확인한 뒤 운영에 반영합니다. 이미 만들어진 고정 배포 주소는 자동으로 새 버전으로 바뀌지 않습니다. 이후 시트의 내용 수정에는 추가 배포가 필요하지 않습니다.

코드의 기본 주소를 바꾸지 않고 다른 시트를 연결하려면 `Equalityact/intro-web` 저장소와 연결된 Vercel 프로젝트의 **Settings → Environment Variables**에서 다음 값을 추가합니다. 환경 변수 값이 기본 설정보다 우선합니다.

```text
이름: TIMELINE_SHEET_CSV_URL
값: 연결할 시트의 CSV 주소
```

변경할 때는 먼저 **Preview** 환경에 설정하고 검토용 브랜치를 다시 배포해 확인합니다. 운영 반영이 승인되면 같은 값을 **Production** 환경에도 설정하고 운영 배포합니다. 환경 변수 변경은 이미 완료된 배포에 소급 적용되지 않습니다. 이전에 이 환경 변수를 설정했다면 값을 비우거나 현재 시트 주소로 바꿔야 기본 연결과 충돌하지 않습니다.

게시 CSV 주소는 브라우저에서 직접 가져오지 않고 `/api/timeline` 서버 경로에서 읽습니다. 별도의 구글 API 키나 서비스 계정은 필요하지 않습니다.

## 4. 갱신 확인하기

- `/timeline`을 열면 최신 시트를 읽고, 열린 페이지는 1분마다 다시 확인합니다. 다른 탭을 보다가 돌아와도 확인합니다.
- 서버 캐시는 1분이며 구글 게시 내용의 갱신에도 시간이 걸릴 수 있어, 수정 내용은 보통 몇 분 안에 보입니다. 즉시 반영을 보장하는 실시간 편집 방식은 아닙니다.
- `/api/timeline`에 `version: 1`과 사건 목록이 나오면 연결된 것입니다.
- 시트 주소가 없거나 접근이 막히면 원래의 정적 타임라인을 유지합니다. 읽는 도중 갱신에 실패하면 이미 불러온 내용을 유지합니다.
- 필수 열 누락, 비정상 링크, 잘못된 행은 일부만 게시하지 않고 해당 갱신 전체를 적용하지 않습니다. 최소 한 사건은 공개되어 있어야 합니다.
- 기존 시기 이름을 유지하면 `#p17`, `#p22` 같은 기존 앵커 주소도 유지됩니다.

## 로컬 확인

현재 시트는 `npm run dev`만으로 연결됩니다. 로컬에서만 다른 시트를 사용하려면 `.env.example`을 `.env`로 복사하고 CSV 주소를 넣은 뒤 서버를 다시 시작합니다. `.env`는 Git에 저장하지 않습니다.

```sh
npm run export:timeline
npm run check
```

`export:timeline`은 저장소의 원고로 가져오기 파일을 다시 만듭니다. 이미 연결한 구글 시트를 덮어쓰거나 수정하지 않습니다. `check`는 기존 원고·링크 검사와 CSV 변환·API 동작 검사를 실행합니다. 실제 구글 시트에 연결되었는지는 별도로 게시 주소와 `/api/timeline` 응답을 확인합니다.
