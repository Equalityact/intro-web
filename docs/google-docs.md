# 구글문서 원고 자동 연동

관리 문서: https://docs.google.com/document/d/1qlEFHPSXBb6pQgUAw_MS8aNMz3XTBqFkB1QSsBdVi9U/edit

## 반영 범위

- 메인 전용 문구·카드 요약·여론조사·리플렛 링크: `0. 메인페이지` 구역.
- 차별금지법이란?: 항목 제목·본문·차별금지사유·영역.
- 일상의 변화: 영역·장면 제목·사례·설명·출처 링크. 새로운 장면도 추가 가능.
- 필요한 이유: 제목·본문. 기존 강조 박스는 해당 문구가 남아 있으면 유지.
- Q&A: 추가·수정·삭제·순서 변경, 검색과 모두 펼치기.
- 타임라인: 시기·사건·본문·개별 링크·색상. 이제 구글문서가 관리 원본.
- 자료: 제목·제작처·설명·자료 링크.
- 정보: 제작·홈페이지·후원 계좌·SNS·이메일·뉴스레터. 자료 페이지와 공통 푸터에 적용.

기존 타임라인 스프레드시트는 이 버전의 화면을 갱신하지 않습니다. `/api/timeline`은 이전 버전 호환용으로 남아 있지만, 새 화면은 모두 `/api/manuscript`를 사용합니다. 자동 반영 버전을 최초 설치/배포한 뒤의 문서 수정에는 재배포가 필요하지 않습니다.

## 원고 작성 규칙

문서는 **한 탭**에서 관리합니다. 현재 연결은 HTML 내보내기이며 여러 탭 전체 수집을 지원하지 않습니다.

1. **제목 1**: `1. ...`~`5. ...`, `더 보기`, `정보`, `0. 메인페이지`. 숫자와 각 구역은 유지하고 제목 문구는 수정할 수 있습니다.
2. **제목 2**: 큰 항목, 일상의 영역, Q&A 질문, 국회 시기, 개별 자료명. 항목은 문서 순서대로 표시합니다.
3. **제목 3**: 각 일상 장면, 타임라인 사건, 메인 카드·여론조사의 개별 항목.
4. **일반 텍스트**: 해당 제목 아래의 본문·답변. 여러 문단과 실제 하이퍼링크를 지원합니다. 본문 색은 편집용이며 사이트 색상은 UI 규칙으로 유지합니다.

### 일상의 변화

영역은 제목 2 → 각 장면은 제목 3 → 그 아래 일반 텍스트로 사례와 설명을 두 문단 이내로 작성합니다. 출처는 해당 문장에 링크를 연결합니다. 기존 원고의 문단을 임의로 잘라내지는 않으므로 이미 들어 있는 문단은 모두 유지됩니다.

기존 장면의 변화 전 문장은 사이트에 보관된 대응 문구를 유지합니다. 새 장면에는 임의의 변화 전 문장을 만들어 붙이지 않고, 입력한 장면과 설명을 한 카드로 표시합니다. 현재 영역 이름을 바꾸거나 장면 제목을 전면 변경하면 기존 변화 전 문구와의 정확한 제목 연결이 끊어져 한 카드로 표시됩니다.

### Q&A

질문은 제목 2, 답변은 일반 텍스트. 질문만 있고 답변이 없는 임시 편집 상태는 게시하지 않고 이전 화면을 유지합니다. 제목 2를 새로 추가하면 문답이 추가되며, 해당 제목과 답변을 삭제하면 웹에서도 제거됩니다. 메인은 앞의 네 문답만 표시합니다. 문답을 읽고 있거나 검색창에 초점이 있으면 읽기를 방해하지 않도록 갱신을 잠시 미룹니다.

### 타임라인

시기는 제목 2, 사건은 제목 3, 내용은 일반 텍스트. 사건 바로 아래 일반 텍스트로 아래 항목을 선택적으로 추가할 수 있습니다. 관리 표시는 웹 본문에는 노출하지 않습니다.

```
[색상: 핑크]
[분류: 입법]
[연도: 2026]
[주체: 국회]
```

색상은 `핑크`(페일 핑크 카드·브라이트 핑크 원), `옐로`(페일 옐로·버터 옐로), `퍼플`(페일 퍼플·퍼플). 생략하면 흰색입니다. 시기 제목 바로 아래에 `[기간: 2028~2032]`를 넣으면 기간 배지가 표시됩니다. 기존 국회는 기간을 생략해도 기존 표시를 사용하며, 새 국회 기간을 추정하지 않습니다.

### 자료

자료 제목은 제목 2. 제작처는 일반 텍스트로 `_ 제작처` 형식, 그 아래 설명 문단, 마지막에는 `링크` 또는 `자료 보기` 문구에 실제 주소를 연결합니다. 연결되지 않은 자료 항목은 게시하지 않습니다.

### 메인 전용 원고

`docs/main-page-appendix.html`은 현재 사이트의 메인 문구를 미리 채운 추가 원고입니다. 이미 문서 끝에 붙여넣었다면 다시 넣지 않습니다. 사이트 이름·메인 슬로건 등 **항목명(제목 2)은 유지**하고 그 아래 내용만 수정합니다. 메인 슬로건은 줄바꿈한 대로 표시됩니다. 여론조사의 세 응답 수치는 `%`를 유지하며, 합계가 99%인 원문을 임의로 보정하지 않습니다.

## 반영 시간과 장애 처리

페이지를 열 때, 탭으로 돌아올 때, 그리고 약 1분마다 확인합니다. CDN 캐시를 포함하면 보통 1~3분 내 반영됩니다. 서버가 구글문서 HTML을 읽으므로 Apps Script·API 키가 필요 없습니다. 문서의 ‘링크가 있는 모든 사용자 → 뷰어’ 접근을 유지합니다.

문서 접근 실패, 잘못된 제목 구조, 답변이나 자료 링크가 빠진 임시 상태에서는 실패 응답을 캐시하지 않으며 기존 정적 원고 또는 이미 표시 중인 마지막 정상 원고를 유지합니다. 편집 후 별도 승인 버튼 없이 공개되므로, 작업 중인 초안은 별도 문서에서 준비하고 완성된 항목을 관리 문서에 붙여넣습니다. 브라우저 저장소에 원고를 영구 보관하지는 않습니다.

## 로컬 실행·검증

Node.js 24 권장. 생성에는 Python 3이 필요합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

이제 `npm run dev`도 PowerShell·cmd·macOS·Linux에서 같은 명령으로 동작합니다. `.env`의 `MANUSCRIPT_DOC_HTML_URL`은 선택적 재정의이며 기본 문서는 `content/manuscript-source.json`에 있습니다. 회사 프록시가 필요한 Node 24 환경에서는 `NODE_USE_ENV_PROXY=1`을 사용할 수 있습니다. Vercel에서는 별도 설정이 필요하지 않습니다.

```sh
npm run generate
npm run check
```

`api/manuscript.js` → `lib/manuscript.cjs`에서 제목 구조와 안전한 링크를 검증한 뒤, `public/assets/js/manuscript.js`가 기존 CSS 컴포넌트로 그립니다. 문서 HTML을 사이트에 직접 삽입하지 않습니다. 기존 문구와 정적 HTML은 접근 실패 때의 기본 원고로 유지합니다.

## 글머리 기호

본문은 구글문서의 글머리 기호 목록·번호 목록을 사용할 수 있으며 중첩 목록과 각 항목의 링크도 유지됩니다. 페이지 제목·질문·장면 제목은 목록으로 바꾸지 말고 제목 1·2·3 스타일을 유지합니다.

## 배포 원칙

작업 확인은 로컬에서 진행합니다. `vercel.json`의 `git.deploymentEnabled`에서 `review/manuscript-update` 브랜치의 자동 배포를 꺼두었으므로 GitHub 업로드만으로 배포하지 않습니다. Vercel 배포는 사용자가 별도로 요청할 때 수동으로 진행합니다.
